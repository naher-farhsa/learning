LangSmith:
A unified observability, tracing & evaluation platform where teams can debug, test and monitor AI apps performance.

Observability: Ability to understand a system's internal state by examining its external outputs, like logs, metrics and traces. It allows to diagnose issues, understand performance, and improve reliability by analysing data generated by system. Essentially, It's about being able to answer "why" something is happening within a system, even if you didn't anticipate problem.

Features: 
1. Observability:

- Observability means understanding what is happening inside your AI app by checking:
  - logs
  - metrics
  - traces
  - inputs/outputs

- In LangSmith, observability helps you see the full internal flow of an LLM app.

- It helps answer why something happened, not just what happened.

- Useful for diagnosing:
  - wrong answers
  - latency/slow responses
  - failed nodes
  - high token usage
  - unexpected workflow paths

Observability = see inside the AI system to debug and improve it

2. Tracing:

- LangSmith tracing records one complete execution of your AI workflow.

- A Trace captures:
  - input
  - output
  - intermediate steps
  - node/tool calls
  - latency
  - token usage
  - errors
  - metadata
  - feedback

- In a graph workflow, each node becomes a run inside the trace.
  Example: START → Retriever → Reranker → LLM Answer → END

- If your workflow has branches, LangSmith shows which path actually executed.

Tracing = debug one full execution step-by-step

3. Monitoring and Alerting:

- Monitoring checks many traces/runs together over time.

- It tracks overall system health using metrics like:
  - latency: P50, P95, P99
  - token usage
  - cost
  - error rate
  - success rate

- Alerting notifies you when something goes wrong.

- Example alerts:
  - latency suddenly increases
  - cost spikes
  - error rate becomes high
  - success rate drops

- It is useful in production because issues often appear as patterns across many runs, not just one trace.

Monitoring = watch many runs over time
Alerting   = notify when metrics go bad

- Latency Optimization

 - Tracks response time: of the AI app from user input to final output.

 - Shows slow components: like LLM call, retriever, tool call, vector search, or external API.

 - Helps find bottlenecks by showing which step is taking the most time inside the trace.

* **Compares different runs** to see which model, prompt, or retrieval setting is faster.

* **Monitors production latency** using metrics like average latency, high latency runs, or slow request trends.

* **Supports alerts** when latency crosses a fixed limit, for example response time greater than 5 seconds.

* **Helps improve speed** by changing model, reducing context size, lowering retrieved chunks, caching results, or optimizing tools.

* **Main goal:** make the AI application faster, stable, and better for real users.


4. Evaluation:

- Evaluation measures the quality of LLM outputs.

- It helps test whether the answer is good, correct, useful, and grounded.

- Evaluation can use:
  - gold-standard datasets
  - custom metrics
  - LLM-as-a-judge
  - semantic similarity
  - custom Python evaluators

- Common metrics:
  - faithfulness
  - relevance
  - completeness
  - correctness
  - similarity

- Evaluation can run:
  - offline: before deployment
  - online: on live traffic

- For RAG: 
  - Faithfulness → Is the answer grounded in retrieved documents? 
  - Relevance    → Does the answer, answers the user’s question?

Evaluation = measure output quality using repeatable tests

5. Prompt Experimentation:

- Prompt experimentation helps compare different prompt versions.

- You can test multiple prompts on the same dataset.

- It supports A/B testing of prompts.

- It tracks which prompt performs better using evaluation metrics.

- Useful for comparing:
  - prompt wording
  - system instructions
  - few-shot examples
  - output format
  - retrieval instructions

- It helps choose the best prompt using data instead of guessing.

Prompt Experimentation = test prompts → compare scores → select best prompt


6. Dataset Creation & Annotation:

- LangSmith helps create datasets for testing and evaluation.

- A dataset can contain:
  - user questions
  - expected answers
  - reference documents
  - labels
  - evaluation examples

- Annotation means humans can label outputs manually.
- Example labels:
  - correct / incorrect
  - relevant / not relevant
  - faithful / hallucinated
  - complete / incomplete

- Datasets are versioned and reusable across projects. Dataset = common questions + expected answers

- For customer support & RAG bot, datasets help test every change in:
  - chunking
  - retrieval
  - reranking
  - prompt
  - model

Dataset Creation = prepare test cases
Annotation       = label outputs as good or bad


7. User Feedback Integration:

- LangSmith can capture real user feedback from production.

- Feedback can include:
  - thumbs up/down
  - ratings
  - comments
  - structured feedback

- Feedback is linked to the exact:
  - trace
  - prompt
  - model
  - input/output
  - workflow state

- This helps understand what users liked or disliked.

- Useful for improving:
  - prompt quality
  - retrieval quality
  - model choice
  - answer accuracy
  - agent behaviour

User Feedback = real user response linked to exact AI run


8. Collaboration:

- LangSmith allows teams to work together on AI app debugging and improvement.

- Team members can:
  - view traces
  - share runs
  - comment on outputs
  - inspect evaluations
  - annotate datasets

- Non-engineers like PMs, QA, and annotators can also inspect runs through the LangSmith UI.

- It supports shared experiment dashboards.

Collaboration = team can inspect, comment, annotate, and compare together

Core Concepts:

- Project: The top-level container or workspace that groups and organizes all your logs, tests, and execution history for a specific application

LangChain Mapping:

- Trace: A complete end-to-end journey of a single input through your system, capturing the full journey from the user's initial question to the final parsed output.

- Run: An individual, isolated step or component action within that journey (e.g., only the LLM generating a response or only the parser structuring the text).

| PROJECT: "My-GenAI-App-Workspace"                                               |
| (The overarching container/database for all your application logs)              |

| TRACE: "Single User Request Journey" [00:37:46]                               |
| (Captures the entire end-to-end execution path from input to output)          |
| +-------------------------------------------------------------------------+   |
|  |                                                                         |   |
|  |[User] ──>[ Prompt ]───────>[ LLM ]───────> [Parser ]         |   |                                                                       
|  |                 ▼                   ▼                   ▼             |   |      
|   |             ( RUN #1 )          ( RUN #2 )           ( RUN #3 )         |   |
|   |           "Format Inputs"     "Call OpenAI"       "Extract JSON"        |   |

LangGraph Mapping:

Trace: Every graph execution can be logged in LangSmith as a trace, capturing the full journey from the initial state input to the final END state.

Run: Each node in the graph becomes a run inside that trace, representing an individual, isolated step or action taken within that execution path.
